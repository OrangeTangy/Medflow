# Architecture and evidence model

Browser → TLS gateway → FastAPI → PostgreSQL. Redis carries ephemeral dashboard notifications and Celery scheduling; PostgreSQL remains the durable source of truth. The API records the network event and processing job in the same transaction. A Redis outage cannot lose a committed event. Celery workers poll the outbox using `FOR UPDATE SKIP LOCKED`, reconcile under a per-doctor advisory transaction lock, and publish only organization-admin and doctor-specific notifications after commit.

OIDC establishes identity, then an operator-provisioned issuer/subject mapping resolves a local user. Roles and organization membership come from the database on every request. Neither doctor IDs supplied by the browser nor claims in a URL establish authorization. A separate auth DB credential can read identity mappings and sessions but cannot read attendance. The web DB login cannot bypass RLS. The worker is a separate trusted processing principal with cross-tenant access; never expose its credential to the web process.

Raw events retain source IDs, event time, receipt time, provider, identity linkage, and a metadata hash. Payloads are deliberately minimized; configure encrypted restricted raw-payload archival in the network relay if required by hospital policy. Derived attendance can be rebuilt. Rebuilds intentionally replace network-derived row IDs; pending corrections retain their requested time/location snapshot even if a referenced derived row disappears.

The reconciler sorts by source event time and source ID. A device interval requires enrolled identity. Interims refresh evidence, missing stops expire at the configured stale threshold, same-location gaps below grace may merge with `grace_merged` confidence, and concurrent devices are unioned. Contradictory concurrent buildings become unknown, never an arbitrary selected facility. Unknown/transit intervals are excluded from network presence totals. Stop-only events do not invent arrivals. Missing-start interims begin at the first observed interim; earlier attendance is never inferred.

The `attendance_sessions` exclusion constraint uses half-open `[start,end)` UTC ranges per organization/doctor. Adjacent transfers are valid, overlaps fail even if application code has a defect. Approved corrections and manual overrides subtract their covered time from derived network intervals. They remain explicitly unverified/manually corrected.

For large deployments, partition network events by organization/month and replay from durable device checkpoints. This implementation currently replays a doctor’s retained history and sweeps active doctors every minute. Benchmark retention sizes before scaling to thousands of staff; historical replay cost is a documented optimization boundary, not an untested scale claim. Run multiple API/worker instances; run exactly one scheduler. Outbox row locks and doctor advisory locks coordinate workers.

All source instants use timezone-aware UTC. Calendar day boundaries use an organization reporting timezone; facility records retain IANA zones. UTC subtraction handles daylight saving correctly. A device’s connection does not establish a person’s physical presence, patient care, productivity, or billable work.

The Sites sandbox uses a different backend so a working private application can be reviewed without AWS or hospital credentials. A single owner-scoped D1 document stores only fictional records with optimistic version checks. It is not the normalized production database and has no trusted-hardware integration. Role switching is sandbox-only, available to the authenticated owner; it is absent from FastAPI.
